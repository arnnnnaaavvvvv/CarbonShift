Reference Guide

Complete CLI Commands & Options

Every command is built for developers and hardened for automated CI/CD pipeline integration.

Primary Command

deppulse scan [path]

Scan project dependencies from package.json and lockfile, score health, and enforce CI threshold policies.

-f, --format <fmt> Output format: terminal (default), json, or markdown.
--fail-on <risks> Comma-separated risk levels to fail CI (e.g. critical,high).
--max-high-risk <N> Maximum allowable high-risk packages before triggering exit code 1.
--allow <pkgs> Temporary exemption list (e.g. legacy-lib@^1.0.0).
--no-cache Bypass local .deppulse/cache/ disk cache and query registries live.
-o, --output <file> Save output to file (creates parent directories safely).
Example: deppulse scan . --format markdown --fail-on critical --output scan-report.md
Inspection

deppulse analyze <package>

Perform a comprehensive telemetry inspection on any registry package without needing a local lockfile.

--version <semver> Target specific published version (defaults to latest dist-tag).
--no-cache Force live telemetry fetch from registry and GitHub.
Example: deppulse analyze lodash@4.17.21
Evaluation

deppulse compare <pkgA> <pkgB>

Direct side-by-side maintenance comparison between two packages to guide technology selection.

pkgA, pkgB Package names with optional versions (e.g. express vs fastify).
Example: deppulse compare express fastify
Auditing

deppulse explain <package>

Inspect the exact mathematical scoring formula, observed telemetry facts, and fatal caps applied.

package Package name to explain (e.g. wrappy).
Example: deppulse explain wrappy

Standardized Exit Codes for CI/CD

Exit 0
Success / Pass
All scanned dependencies pass the configured health policy.
Exit 1
Policy Breach
One or more dependencies violate failOnRisk or exceed limits.
Exit 2
Usage / System Error
Missing manifest, invalid arguments, or parse error.

Guarantees

The Four Non-Negotiable Hard Rules

DepPulse is engineered around developer trust, safety, and operational transparency.

01

Strict Read-Only Execution

DepPulse never executes project install scripts, never invokes lifecycle hooks, and never alters your lockfiles or source code. Verified by automated filesystem-diff tests.

02

Zero Token Leakage

No API keys or tokens are ever logged, cached to disk, or included in JSON/terminal reports. All URLs and HTTP errors are automatically scrubbed through regex redaction.

03

Missing Data is Never Penalized

Sparse telemetry from unlinked GitHub repositories or private registries only lowers the confidence metric—it never deducts health points or manufactures false alarms.

04

Decoupled Security Context

Security advisories (CVEs) are presented purely as orthogonal context annotations. A zero-day CVE on a well-maintained library never misclassifies it as abandoned.
